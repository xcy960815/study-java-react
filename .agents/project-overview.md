# Project Overview

## Purpose

`study-java-react` is a React admin frontend for a Java-oriented backend study/project system. It includes login/register flows and typical management modules:

- System management: users, roles, menus, data dictionaries.
- Monitoring: operation logs, server metrics, daily business report.
- Business pages: orders and goods.
- Hidden placeholders for `ollama` and `deepseek` routes until real business integration is added.

The repository is frontend-only. It expects backend APIs to be reachable through Vite/Nginx proxy paths configured by environment variables.

## Main Technology

- React 19 with `react-router-dom` 7.
- TypeScript 5 with strict compiler options.
- Vite 7 with React and Tailwind CSS plugins.
- Ant Design 6 for UI.
- Zustand for login actions.
- Axios for HTTP requests and token refresh.
- pnpm 10.33.0 as declared in `package.json`.

## Package And Source Structure

```text
src/
  apis/          Typed API wrappers by business domain.
  assets/        Static source assets imported by the app.
  components/    Reusable UI components.
  enums/         Shared enum values.
  hooks/         Custom React hooks.
  layout/        Main authenticated shell and sidebar menu generation.
  plugins/       Project/Vite plugins, including file-structure generation.
  router/        Browser router, route handles, auth guards, redirects.
  store/         Zustand exports and store modules.
  utils/         Request, token, event bus, system style helpers.
  views/         Page-level modules.
```

Important root files:

- `package.json`: scripts, dependencies, lint-staged config, package manager.
- `vite.config.ts`: environment loading, proxy setup, chunking, aliases, plugins.
- `eslint.config.js`: ESLint flat config for TS/TSX, React hooks, React refresh.
- `tsconfig*.json`: TypeScript project references and app/node compiler settings.
- `Dockerfile` and `nginx.conf`: production image and static SPA hosting.
- `.github/workflows/quality.yml`: CI lint/build checks.
- `.github/workflows/docker-build.yml`: tag-triggered Docker Hub build/push workflow.

## Runtime Shape

Local development:

- Vite reads mode-specific env files from `env/`.
- `pnpm dev` runs mode `daily`, using `env/.env.daily`.
- The dev server proxies `VITE_API_DOMAIN_PREFIX` to `VITE_API_SERVER_DOMAIN` and rewrites it to `VITE_API_SERVER_DOMAIN_PREFIX`.
- `src/plugins/file-structure.ts` exposes `/api/project/file-structure` in dev.

Production:

- `pnpm build:prod` runs `tsc -b` then `vite build --mode prod`.
- Build output goes to `dist/`.
- Docker builds with Node 22, then copies `dist/` into an Nginx image.
- `nginx.conf` serves the SPA with `try_files ... /index.html`, long-cache static assets, and a `/prod-api/` proxy.

## Generated Or Do-Not-Edit Paths

- `node_modules/`: dependency install output.
- `dist/` and `dist-ssr/`: Vite build output.
- `public/file-structure.json`: generated by `src/plugins/file-structure.ts`; do not edit manually.
- `node_modules/.tmp/*.tsbuildinfo`: TypeScript build cache referenced by `tsconfig.app.json`.
- `.husky/_/`: Husky internal shim files.
- `pnpm-lock.yaml`: update via `pnpm install`/`pnpm add`, not manual edits.

## Current Limitations

- No backend service is included.
- No test runner, test script, or test files are currently present.
- No dedicated docs generation script exists.
